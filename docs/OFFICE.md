# Counsel for Word

The repository includes an add-in-only XML manifest and an Office.js task pane. It reads selected text or the main Word document body into an editable preview, saves that preview as a new Counsel source or draft, loads saved Counsel drafts, and inserts the preview after the current selection with Word tracked changes. These are user-clicked actions; no model or external delivery is triggered.

## Hosting and installation

Serve the `office/` assets at `/office/` on the **same HTTPS origin** as Counsel and `/agent/v1`. The checked-in manifest targets `https://localhost:3443`; it requires a locally trusted TLS certificate and an HTTPS reverse proxy to the authenticated team-mode server. This repository does not install certificates, change machine trust, or expose a server. The current personal mode rejects reverse proxies and uses HTTP: use a separate authenticated team-mode deployment for the HTTPS Word add-in.

For a different deployment, `require('./office/manifest').officeManifest('https://counsel.example')` generates the manifest with the correct origin. Serve that output as `application/xml`. Do not edit the URL to a site you do not control: the task pane can read text when the user clicks the read action. No bearer key belongs in a manifest URL, query parameter, document settings, or browser storage.

Only the `/office/` asset responses need Office framing and Office.js script permissions. They need `script-src 'self' https://appsforoffice.microsoft.com`, `connect-src 'self'`, `style-src 'self'`, and a configured `frame-ancestors` list for the actual tenant/Office hosts used. Remove `X-Frame-Options` only on these assets. Keep the normal Counsel app's framing policy unchanged. Office.js can require additional CDN and host permissions depending on the installed Office runtime; inspect host diagnostics rather than allowing arbitrary sources. Use HTTPS and the authenticated team-mode host's existing origin checks.

Sideload the generated XML using Word's **Add-ins → More Add-ins → My Add-ins → Upload My Add-in**, where the client and tenant permit sideloading. On Mac, Microsoft's documented alternative is to copy the XML into `~/Library/Containers/com.microsoft.Word/Data/Documents/wef` and reopen Word. A managed organization may require administrator deployment through its trusted catalog instead. [Microsoft's sideloading guidance](https://learn.microsoft.com/en-ca/office/dev/add-ins/testing/sideload-office-add-ins-for-testing) and [Mac instructions](https://learn.microsoft.com/en-us/office/dev/add-ins/testing/sideload-an-office-add-in-on-mac) describe the host-specific steps.

In Counsel, create an assistant connection key restricted to the intended matter(s). Paste it into the Word pane. The pane clears the password field and keeps the key in a JavaScript closure only. Closing or disconnecting clears that capability; revoking the key in Counsel invalidates subsequent requests. A read key can load drafts. Saving text requires a write key. The existing assistant API rechecks member status, key expiry/revocation, matter access and write permissions on each request. Import calls use unique request IDs for the API's idempotency contract. Every save creates a new record; it does not overwrite an existing source or draft.

## Text and tracked changes

The preview transfers plain text up to 200,000 characters. It excludes Word headers, footers and other stories outside `document.body`. Existing formatting, tables as structures, fields, comments, image content, footnotes, signatures and revision history are not preserved by this text bridge. “Save as source” creates extracted text through `import_text`, rather than retaining a complete original `.docx`; use Counsel's ordinary upload for exact original-file retention.

Before insertion, review the visible preview and underlying evidence. The insert action requires `WordApi 1.4`, loads the existing change-tracking mode, enables `TrackAll`, inserts at the end of the current selection, and restores the previous mode. It fails explicitly on older hosts, without silently inserting untracked text. It neither accepts nor rejects existing changes. Word attributes edits according to its host behavior and identity. [Microsoft's tracked-change API guidance](https://learn.microsoft.com/en-us/office/dev/add-ins/word/manage-tracked-changes) and [ChangeTrackingMode reference](https://learn.microsoft.com/en-us/javascript/api/word/word.changetrackingmode?view=word-js-preview) support this implementation.

## Evidence and limits

Automated tests cover manifest origin generation, same-origin scoped requests without persisted credentials, complete paginated draft reads, unsupported-host rejection, insertion sequencing and restoring tracking mode after a host error. These use a simulated Office object model. No live Word desktop/web host, tenant catalog, certificate trust, third-party cookie policy, sideloading policy or Microsoft Marketplace certification is claimed verified. A real host/tenant acceptance run remains necessary before organizational rollout. [Microsoft's manifest hosting requirements](https://learn.microsoft.com/en-us/office/dev/add-ins/develop/add-in-manifests) require secure hosting for Office on the web.
